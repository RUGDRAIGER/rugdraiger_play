A) PÁGINA WEB — Rugdraiger Play
================================================================================

--- URL y despliegue ---

  Producción: https://rugdraiger.github.io/rugdraiger_play/
  Base path build: /rugdraiger_play/
  Carpeta fuente: web/
  Build: cd web && npm run build:pages
  Deploy: scripts/deploy-pwa.sh → rama gh-pages
  APK descargable desde web: /rugdraiger_play/apk/rugdraiger-play.apk

--- Stack tecnológico ---

  React 18 + TypeScript + Vite 6
  Estado: Zustand (4 stores)
  Persistencia: Dexie (IndexedDB) — DB "RugdraigerPlayerDB" v3
  Metadatos audio: jsmediatags (ID3/APIC en cliente)
  Reproducción: HTMLAudioElement + Web Audio API (ecualizador real)
  PWA: vite-plugin-pwa (service worker, manifest)
  Capacitor en web/ existe pero NO es la app Android oficial

B) APP ANDROID NATIVA — Flutter (última versión)
================================================================================

--- Qué es ---

  App NATIVA Flutter (NO WebView, NO Capacitor).
  Replica interfaz y mecánica de la web descrita en sección A.
  Carpeta: rugdraiger_player/
  Package Android: com.rugdraiger.rugdraiger_player
  Nombre visible: Rugdraiger Play

--- APK publicado ---

  Archivo: apk/rugdraiger-play.apk (~25 MB ARM64)
  URL: https://rugdraiger.github.io/rugdraiger_play/apk/rugdraiger-play.apk
  Build: ./scripts/build-apk.sh (Flutter, JDK 17, Android SDK, compileSdk 36)
  Copia web: web/public/apk/rugdraiger-play.apk

--- Stack tecnológico ---

  Flutter 3.x / Dart >=3.4
  Estado: flutter_bloc (PlayerBloc, LibraryBloc)
  DB: sqflite (SQLite) — rugdraiger.db
  Escaneo: on_audio_query (MediaStore) + file_picker (carpeta específica)
  Audio: just_audio + just_audio_background + audio_session
  EQ UI: EqualizerService (SharedPreferences) — UI estilo web; DSP nativo limitado
  Permisos: permission_handler (READ_MEDIA_AUDIO, notificaciones)

  Icono app: assets/icons/app_icon.png (copiado de web icon-512)
  Launcher Android: mipmaps generados en build-apk.sh desde app_icon.png

--- Servicios ---

  audio_service.dart      — just_audio, URIs file/content, cola, volumen, mute
  music_repository.dart   — escaneo MediaStore + carpeta, CRUD SQLite
  database_helper.dart    — songs, playlists, playlist_songs, recently_played
  equalizer_service.dart  — presets/bandas en SharedPreferences

--- Reproducción audio (Flutter) ---

  - Rutas: Uri.file() o Uri.parse(content://...)
  - Validación archivo existe antes de play
  - ConcatenatingAudioSource + MediaItem (just_audio_background)
  - Fallback sin MediaItem si falla background init
  - audio_session configurado en main.dart (AudioSessionConfiguration.music)
  - Notificación Android foreground al reproducir
  - Errores visibles en mini player (errorMessage)

--- Escaneo biblioteca (Flutter) ---

  1) ScanLibraryEvent → on_audio_query querySongs (todo el dispositivo)
  2) ScanFolderEvent → file_picker carpeta → scanDirectory recursivo
  Formatos: mp3, flac, aac, wav, ogg, m4a, alac, aiff, opus, wma

--- Formatos / permisos Android ---

  AndroidManifest: READ_MEDIA_AUDIO, READ_EXTERNAL_STORAGE (≤32),
  INTERNET, WAKE_LOCK, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK,
  POST_NOTIFICATIONS
  compileSdk: 36 (app + subprojects en android/build.gradle.kts)

--- Paridad web ↔ Flutter (estado actual) ---

  IMPLEMENTADO en Flutter:
    - Navegación y layout móvil equivalente
    - Colores y tipografía alineados
    - Escaneo dispositivo + carpeta específica
    - Menú ⋮ canción y detalle álbum con lista
    - VolumeFader en mini/full player
    - EQ faders verticales UI
    - Icono app real
    - Reproducción nativa con just_audio

  DIFERENCIAS / pendientes vs web:
    - Web: File System Access API / picker navegador; Flutter: MediaStore + file_picker
    - Web: EQ procesa audio (Web Audio API); Flutter: EQ guarda prefs, no DSP nativo completo
    - Web: artwork iTunes backfill; Flutter: artwork desde MediaStore
    - Web: Dexie blobs por canción; Flutter: paths URI del sistema
    - Web: sidebar desktop; Flutter: solo layout móvil
    - Web: PWA offline; Flutter: app instalada APK

--- Objetivo para otra IA ---

  La WEB es la referencia de diseño, UX y funcionalidades.
  La app FLUTTER debe seguir evolucionando hacia paridad 1:1 con la web,
  manteniendo ventajas nativas (MediaStore, background playback, notificaciones).
  NO reemplazar Flutter por Capacitor/WebView.
