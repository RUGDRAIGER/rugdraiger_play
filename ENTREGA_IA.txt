--- Carátulas en la WEB (referencia para la APK) ---

  Flujo en ArtworkDisplay (web/src/components/ui/ArtworkDisplay.tsx):
    1) resolveArtworkSrc() — artwork embebido del escaneo (jsmediatags APIC)
    2) Si no hay imagen → fetchArtworkUrl() vía iTunes Search API
    3) Al encontrar URL → updateSongArtwork() + cache en store/IndexedDB

  artworkService.ts — lógica iTunes:
    - normalizeQuery() limpia paréntesis/corchetes del título
    - isGenericAlbum(): vacío o "unknown album" (NO trata "Music" como genérico)
    - isGenericArtist(): vacío o "unknown artist"
    - Orden de búsqueda fetchArtworkUrl():
        a) Si hay título y álbum genérico → song: "{artist} {title}"
        b) Si álbum conocido → album: "{artist} {album}"
        c) Fallback → song: "{artist} {title}"
    - pickBestMatch(): puntúa artista/álbum/título; si score=0 usa results[0]
    - upgradeArtworkSize(): URLs 100x100 → 600x600

  scannerService.ts — metadata para carátulas:
    - jsmediatags lee APIC/picture del archivo
    - inferMetadataFromPath() + parseFilenameMetadata() desde nombre/ruta
    - Ejemplo: "Fire Force - Opening 1  Inferno.mp3"
        → artista: Fire Force, título: Opening 1 Inferno
    - enrichSongsArtwork() en libraryStore tras cargar/escanear biblioteca

  backfillArtworks() en libraryStore:
    - Recorre canciones sin artwork
    - Comparte carátula por álbum si artista/álbum no son genéricos
    - Delay 120 ms entre peticiones iTunes

--- Carátulas en la APK (paridad con web) ---

  Orden de resolución (ArtworkCache.loadForSong):
    1) Cache memoria (ArtworkCache.get)
    2) song.artwork en memoria (si existiera)
    3) Cache por álbum (_albumCache)
    4) MediaStore queryArtwork (JPEG y PNG, id MediaStore real)
    5) Extracción embebida del archivo (EmbeddedArtworkExtractor + Kotlin nativo)
    6) iTunes Search API (ArtworkFetcher — igual que artworkService.ts web)

  ArtworkWidget / LargeArtworkWidget:
    - Muestra Image.memory cuando hay bytes
    - Spinner mientras carga; placeholder nota musical si falla todo
    - errorBuilder reintenta carga remota

  Metadata para búsqueda iTunes:
    - Si MediaStore dice "<unknown>" / "Music", se infiere del nombre archivo
    - "Fire Force - Opening 1  Inferno.mp3" → artista Fire Force, título con Inferno
    - Sin inferencia, iTunes no encuentra carátula (término "<unknown> ..." falla)

  Limitaciones conocidas:
    - Carátulas iTunes requieren INTERNET en el dispositivo
    - No se persisten bytes de carátula en SQLite (solo cache sesión en memoria)
    - MP3 sin APIC y sin match iTunes → placeholder
    - queryArtwork MediaStore suele fallar si no hay arte indexado en el sistema

--- Reproducción audio (Flutter) ---

  - MainActivity extiende AudioServiceActivity (obligatorio just_audio_background)
  - JustAudioBackground.init() en main() ANTES de runApp()
  - Rutas: Uri.file() o Uri.parse(content://...)
  - resolveForPlayback() re-resuelve URI content:// fresco desde MediaStore
  - ConcatenatingAudioSource + MediaItem (just_audio_background)
  - Fallback playlist/URI individual si falla background tag
  - audio_session.setActive(true) antes de reproducir
  - Notificación Android foreground al reproducir
  - Errores visibles en mini player (errorMessage)

--- Permisos al abrir (Flutter) ---

  - Pantalla _PermissionGate en main.dart (no se puede omitir)
  - Botón "PERMITIR ACCESO" → PermissionService.requestMediaAccess()
  - Si denegado permanente → "ABRIR AJUSTES"
  - Tras conceder → MainScaffold(autoScanOnStart: true) si biblioteca vacía
  - AndroidManifest: READ_MEDIA_AUDIO, READ_MEDIA_IMAGES, READ_EXTERNAL_STORAGE (≤32)

--- Escaneo biblioteca (Flutter) ---

  1) ScanLibraryEvent → on_audio_query querySongs (todo el dispositivo)
     + inferencia metadata desde filePath (_fromOaqSong)
  2) ScanFolderEvent → file_picker carpeta → scanDirectory recursivo
     + inferencia metadata desde path
  3) Tras cargar → ArtworkCache.enrichAll() precarga carátulas (MediaStore + iTunes)
  Formatos: mp3, flac, aac, wav, ogg, m4a, alac, aiff, opus, wma

--- Formatos / permisos Android ---

  INTERNET, WAKE_LOCK, FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK,
  POST_NOTIFICATIONS

--- Paridad web ↔ Flutter (estado actual) ---

  IMPLEMENTADO en Flutter:
    - Navegación y layout móvil equivalente
    - Colores y tipografía alineados
    - Escaneo dispositivo + carpeta específica
    - Menú ⋮ canción y detalle álbum con lista
    - VolumeFader en mini/full player
    - EQ faders verticales UI
    - Icono app real
    - Reproducción nativa con just_audio + AudioServiceActivity
    - Permisos obligatorios al abrir
    - Limpiar biblioteca (HomeScreen)
    - Inferencia metadata desde nombre/ruta de archivo (port web scannerService)
    - Carátulas: embebidas + iTunes + MediaStore (solo álbum real, port web artworkService)
    - Carga carátulas bajo demanda en widgets (sin prefetch masivo al escanear)
    - Reproductor full: sin menú ⋮ ni barra inferior (LIKE/LYRICS/QUEUE/OUTPUT)
    - Botón corazón funcional → sección Me gusta en Inicio + pantalla Favoritos
    - Sección Lo más escuchado (top 4 por play_count) en Inicio
    - Mini player sin barra de volumen
    - Reproductor: menú ⋮ con «Buscar imagen de carátula» (iTunes + persistencia en disco)
    - Layout responsivo en reproductor (compacto para pantallas ~720×1600)

  DIFERENCIAS / pendientes vs web:
    - Web: File System Access API / picker navegador; Flutter: MediaStore + file_picker
    - Web: EQ procesa audio (Web Audio API); Flutter: EQ guarda prefs, no DSP nativo completo
    - Web: artwork persistido en IndexedDB (URLs/data); Flutter: cache solo en memoria
    - Web: jsmediatags APIC en cliente; Flutter: ID3 nativo + iTunes si no hay APIC
    - Web: Dexie blobs por canción; Flutter: paths URI del sistema
    - Web: sidebar desktop; Flutter: solo layout móvil
    - Web: PWA offline; Flutter: app instalada APK
    - Carátulas iTunes en APK requieren conexión a internet
